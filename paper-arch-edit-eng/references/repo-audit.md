# 代码库审计规范

## 扫描项（脚本 + 人工）
- 架构入口：train/eval 脚本、模型注册表、配置文件
- 层注册：是否有 registry / nn.Module 工厂 / hydra / argparse 开关
- 候选落点的上游输出形状与下游期望（用 hooks 或 print 实测，不靠猜）
- 现有测试：pytest 目录、覆盖率、是否有等价性测试
- 依赖：torch/CUDA 版本、torch.compile、分布式、混合精度
- 侵入级别评估：
  - 低：加 hook 或加可选模块，默认关闭
  - 中：修改现有 forward 分支，需 feature flag
  - 高：改接口签名或数据流，需单独分支 + 回归基准

## 产出
审计表 + 一句话结论，格式：
"机制 M 落在 F::f，接口 f(x)->y 形状 ____，侵入级别 ____，
 回滚方式 ____，现有测试覆盖 ____。"

## 反模式
- 未实测形状就写接口契约
- 忽略训练/推理态差异（BN、dropout、量化）
- 忽略混合精度下的 dtype 提升/截断
