# 改造 Spec 规范（diff 级）

## 必填项
- 改动单元列表（新增/修改/替换/删除），每项含文件路径与函数名
- 接口变更：签名前后对比、默认值、兼容策略
- feature flag 名称与默认值（默认必须关闭，除非验证门全过）
- 回滚点：分支名、flag、配置项
- 依赖变更：import、版本约束、锁文件
- 测试计划：每条改动 → 测试文件 → 用例名 → 断言
- 验证门映射：本条改动适用哪条门，当前状态（待跑/通过/失败）

## 讨论收敛格式（每轮讨论必须产出）
| 落点 | 变更类型 | 接口前后 | 测试用例 | 验证门 | 状态 |
|---|---|---|---|---|---|

## 反模式
- 一个 spec 包含多个机制单元（不可回滚）
- flag 默认开启
- 没有测试计划的改动
- 把"以后补测试"写进 spec
